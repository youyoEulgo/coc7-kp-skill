# Skill: CoC7_Custom_LogFormat

## Role

跑团日志写作规范。本Skill定义了日志的记录格式，确保每次跑团的log风格统一、便于阅读。

当记录log时，必须调用本Skill。

---

# 第一章：核心原则

## 忠实纪录，不得简写

log必须忠实还原跑团过程中发生的所有RP对话、场景氛围和检定过程。**不得自行省略、概括或精简。** 如果KP和PL之间有完整的对话，log中必须原样保留。如果场景有详细的氛围描写，log中也要同等详细地呈现。

## 整体风格

日志采用**叙述体+剧本式**风格，类似规则书第一章的游戏范例。读起来应该像一篇小说或纪实文学，而不是流水账或条目列表。

- KP的发言是叙述者的旁白——描述场景、推进剧情、宣布结果
- 玩家的发言用角色名引出——标记谁在行动、谁在说话
- 骰子结果忠实嵌入，不带引导性语言
- 全文不出现粗体、表格、代码块等标记
- 使用全角横线作为场景分隔

正确示例（非实际模组内容）：
————————————————————
场景 · 釜村家
————————————————————
KP：田所浩一来到釜村家门前，按响了门铃。过了片刻，门打开了——釜村徹站在门内。他的脸色蜡黄，眼窝深陷，整个人瘦了一圈。但他的态度却出奇地友好——他将田所迎进屋内，引领他穿过走廊来到客厅。客厅收拾得整整齐齐，茶几上甚至准备好了茶点。

田所浩一：道了一声节哀。

KP：釜村徹垂下眼睛，沉默了片刻，然后平静地回答道。

釜村徹："都是过去的事了，不要再提了。"

检定：心理学——1d100 → 95 > 70 → 失败。

KP：田所注视着他的表情，试图从那副憔悴的面容中找到什么破绽——闪躲、强忍、或者刻意转移话题的痕迹。但什么也没有。釜村徹说这句话的时候，就像在陈述一件与己无关的旧事。

错误示例：
————————————————————
田所来到釜村家，釜村徹迎接他。田所道节哀，釜村说过去了。心理学失败。
————————————————————

# 第二章：格式细则

## 2.1 KP的叙述

以 `KP：` 开头，负责描述场景、宣布结果、推进剧情。不做引导性提问（如"你要做什么？""先做一个检定"）。

```
KP：子弹正中胸口。瘦高个闷哼一声，仰面倒在地上。枪从手里滑脱。
```

## 2.2 玩家的行动与对话

声明动作用 `角色名：` 开头。如果同时有行动和台词，用逗号分隔。

如果PL的描述很简洁（如"侦查一下"），**不可原样照抄**。必须根据上下文，替PL润色为符合角色风格的叙事描写。

```
PL原话：侦查一下。
log中写成——
佐藤浩二：蹲下身，仔细检查门锁。摸了摸黄铜表面，又凑近看了看锁舌和门框的缝隙——安装得不太专业，有两颗螺丝钉歪了。接着侧身绕到窗边，透过碎掉的玻璃角往里扫了一眼。
```

PL原话：我要检查一下那封信。
log中写成——
林夜：拿起信封，翻到背面检查封口的蜡印是否完好。接着抽出信纸，快速扫了一遍，目光停留在最后的署名上。

```
林夜：检查这张便签。

渡边玲：从掩体后探出枪口，"放下枪。我不像他脾气那么好。"
```

## 2.3 RP对话的完整记录

log中必须完整保留KP和PL之间的所有RP对话，包括：

- NPC的每一句台词
- PL角色说的每一句话
- 角色内心活动（如果有）

不能因为"内容太长"或"已经知道剧情"就省略或概括。例如，釜村徹关于"森林中树木倒下"的那段独白，在log中必须完整出现，不能简化为"釜村说了一番关于存在的哲学言论"。

## 2.4 场景氛围的忠实还原

跑团过程中KP描述的场景氛围——光线、气味、声音、触感——在log中必须有同等程度的描写。如果实际游戏中有多个段落的场景描写，log中也应当逐段记录，不可合并。

## 2.5 前缀规则

不同内容使用不同前缀：

- **场景开头/纯叙事描写**：无前缀，直接叙述
- **KP宣布结果或推进**：`KP：`
- **玩家行动**：`角色名：`
- **玩家行动+台词**：`角色名：行动描述，"台词"`
- **检定结果**：`检定：`

```
场景 · 釜村家

田所浩一来到釜村家门前，按响了门铃。过了片刻，门打开了——釜村徹站在门内。

KP：子弹正中胸口。瘦高个闷哼一声，仰面倒在地上。

佐藤浩二：蹲下身，仔细检查门锁。

检定：侦查——1d100 → 45 ≤ 50 → 成功。
```

## 2.6 角色说的话

所有从角色口中说出来的话，不论PL还是NPC，都用双引号包裹。

```
佐藤浩二："你同伙已经倒了。把枪扔出来，给你留条活路。"
```

## 2.7 文字/书籍/便签

便签、报纸、书籍、碑文等文字内容用直角引号包裹，以区别于人物对话。

```
便签上写着：「只管前进吧 已经没有退路了」

报纸头版：「xx线末班电车遭遇大规模恐怖事件」
```

## 2.8 骰子结果

以 `检定：` 开头，纯事实记录。格式统一。

```
检定：侦查——1d100 → 45 ≤ 50 → 成功。

检定：锁匠——1d100 → 27 ≤ 01 → 失败。伤害：1d10 → 9。

检定：重伤判定——9 ≥ 7 → 触发。体质检定（昏迷判定）——1d100 → 57 ≤ 50 → 失败。
```

对抗类内容直接陈述：

```
恐吓对抗——佐藤浩二50% vs 黑手党A意志50%。佐藤：1d100 → 79 → 失败。黑手党A：1d100 → 85 → 失败。
```

## 2.9 战斗流程

行动顺序在战斗开始时列出，每个行动前标注角色名。

战斗轮之间用横线分隔。每轮结束时标注"第X轮结束"。

## 2.10 日志末尾

log末尾不写角色状态汇总——角色卡和状态独立管理，需用时单独查询。

# 第三章：常见错误

| 错误类型 | 错误示例 | 正确做法 |
|:---------|:---------|:---------|
| 省略对话 | 釜村说了一番话 | 完整引用原句 |
| 概括描写 | 屋里很诡异 | 描述具体的光线、气味、声音 |
| 跳过过程 | 田所调查了几个房间 | 按顺序记录每个房间的调查详情 |
| 简写检定 | 侦查成功 | 检定：侦查——1d100 → XX ≤ XX → 成功 |

# 第四章：格式速查

```
【场景开头/叙事】纯叙事，无前缀

【KP叙述】KP：内容

【PL行动】角色名：行动内容

【PL行动+台词】角色名：行动描述，"台词" 

【PL纯台词】角色名："台词"

【PL简洁指令润色】"侦查一下" → log写「角色名：详细叙事」

【RP对话】完整保留，不可省略

【检定结果】检定：技能/判定——1d100 → X ≤ Y → 成功/失败。

【人物说的话】"内容"

【文字/便签/报纸】「内容」

【场景分界】————————————————————
```

## 强制记住的关键规则

**log不是复盘笔记，是故事的重现。** 读log的人应该能感受到和当时跑团时一样的氛围和情感。一切省略都是对真实经历的损害。被忠实记录下来的，才是完整的log。
